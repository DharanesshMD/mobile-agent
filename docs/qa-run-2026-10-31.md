## Bugs
Fixed in this run (each with a test where it is code):
- **A. Responsive layout never collapsed** (`web/index.html`): the media-query rules sat above the base `.side`/`.panel`/`.menu-btn` rules and lost. Moved to the end of the stylesheet.
- **B. Tag overlapped bot names** (`web/index.html`): the name now stops before the tag.
- **C. The owner never got the answer when the model replied in plain text** (`agent/orchestrator.py` `_decide`): prose with no JSON is now shown as the reply; the "not valid JSON" correction now says "same request, do not mention this". Tests `ProseReplies`.
- **D. "Can't check the battery"** (`agent/checks.py`, `agent/device.py`, `prompts/orchestrator.md`): `phone_check` kind `battery`. Tests `BatteryCheck`.
- **E. "Ask me first" dropped from the worker goal** (`prompts/orchestrator.md`).
- **F. A healthy launch was killed by a background system service crash** (`agent/graph.py`): on the Games phone `com.android.bluetooth` crashed 4 times and the task was stopped as "App keeps crashing". Only packages with a launcher icon count now. Test `test_a_background_system_service_crashing_does_not_stop_the_task`.
- **G. Master delegated a stale goal** (`prompts/orchestrator.md`, `prompts/master.md`): "open Clash of Clans" went out as "open Shattered Pixel Dungeon".
- **H. Master chose by guesswork** (`agent/phones.py`, `agent/jobs.py`, `agent/device.py`): the directory now lists each phone's installed apps (remembered across restarts, a sleeping phone is not woken to ask). Master also answers in its own chat after every delegated success (was only after a move or reroute), and may not start an install the owner did not ask for (rule added; not exercised live). Test updates in `test_hybrid.py`, `test_master.py`.
- **I. Duplicate phone bots with the same name** (`agent/master.py`): a second phone gets "Name 2". Test in `test_remote.py`.
- Added `scripts/reset_fresh.py`: wipes chats, tasks, memory, routines, screenshots and traces, keeps vault, paired devices and the phones' bots, backs the database up first.

Open:
- **Real-phone app task fails when the "phone" is the shared emulator** (scenario 7). Reproduce: pair the app on the emulator, send any task to its bot while the server's uiautomator2 reader is alive. Proposed fix: stop the resident reader for the duration of a phone-app job on the same device, or only test the app on a real phone.
- **Phone bot greeting says "is connected" forever**, also while offline (the Mobile tab and the chat reply are honest; the first message is stale).
- **Routine quality**: first fire says "routine" and no time; the model reports UTC, the server runs in local time (IST).
- **Job results carry the Google account address** (contacts count result: "398 in Google Contacts for <address>") into the job result and the library title. Mask account addresses in results.
- **Model routing is not deterministic**: Master chose the emulator for Shattered Pixel Dungeon twice before the installed-apps fix. Now correct, but it stays a model decision.
- **Memory pressure**: swap 8.5 of 9.2 GB used during the run. Quit other apps before recording the demo; the Lima VM adds 1 to 2 GB.
- **The Mobile panel is behind a toggle below 1100 px** (the original intent, now that the CSS works), so a narrow pane no longer shows the phone all the time.
- A queued task that the bot chained to a running one is skipped when a restart interrupts the first.

## What a first-time user would feel (top 5)
1. **A cold first screen**: Assistant's chat is empty ("No messages yet"), Master immediately warns "Assistant has no focus yet", and the phone bot is called `sdk_gphone64_arm64`. Give the Assistant a one-line hello, wait before warning, and name the phone bot "My phone" until the owner renames it.
2. **Good honesty, too much repetition**: stops and failures produce two near-identical messages, and Master's chat shows a raw "Games phone finished: <goal> <result>" note before the friendly answer.
3. **Speed is fine for chat (1.3 to 3.8 s) but a phone step takes 4 to 8 s**; the "Starting... / Waiting for you / Waiting for an earlier task" statuses are what make the wait bearable. The Games phone cold start (24 s) shows a clear card.
4. **Cards work well**: approval, confirm, choice (the 5-minute routine) and handoff all read clearly and resume correctly.
5. **On a phone-sized window the old layout was unusable** (fixed in this run); check it again on a real phone before the demo.
