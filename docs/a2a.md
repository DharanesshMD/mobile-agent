# A2A service: other agents hire this agent (plan, 3 Nov 2026)

Goal: any A2A-speaking agent can connect, ask for work (phone tasks, link and APK checks, pictures, answers from memory), get properly typed results (text, data, files, reports), and every input and output is stored in the database and shared with all bots through one knowledge store that retrieves well.

## Protocol facts (checked against the official spec, a2a-protocol.org, 1.0.0)
- Agent Card at `/.well-known/agent-card.json`. 1.0 card: `name, description, supportedInterfaces[{url, protocolBinding:"JSONRPC", protocolVersion:"1.0", tenant}], provider, version, documentationUrl, capabilities{streaming, pushNotifications, extendedAgentCard}, securitySchemes, securityRequirements, defaultInputModes, defaultOutputModes, skills[{id,name,description,tags,examples,inputModes,outputModes}], iconUrl`.
- JSON-RPC 2.0 methods (1.0): `SendMessage, SendStreamingMessage, GetTask, ListTasks, CancelTask, SubscribeToTask, CreateTaskPushNotificationConfig, GetTaskPushNotificationConfig, ListTaskPushNotificationConfigs, DeleteTaskPushNotificationConfig, GetExtendedAgentCard`.
- 1.0 shapes (ProtoJSON, camelCase): `Task{id, contextId, status{state, message, timestamp}, artifacts[], history[], metadata}`, `Message{messageId, contextId, taskId, role:"ROLE_USER"|"ROLE_AGENT", parts[], metadata, extensions, referenceTaskIds}`, `Part` = exactly one of `text | raw (base64) | url | data` plus `filename, mediaType, metadata`, `Artifact{artifactId, name, description, parts[], metadata}`.
  States: `TASK_STATE_SUBMITTED, _WORKING, _COMPLETED, _FAILED, _CANCELED, _INPUT_REQUIRED, _REJECTED, _AUTH_REQUIRED`. Stream events: `StreamResponse` holds one of `task | message | statusUpdate | artifactUpdate` (`TaskStatusUpdateEvent{taskId, contextId, status, metadata}`, `TaskArtifactUpdateEvent{taskId, contextId, artifact, append, lastChunk}`), sent as SSE `data: {"jsonrpc":"2.0","id":<id>,"result":<StreamResponse>}`.
- Errors: -32001 TaskNotFound, -32002 TaskNotCancelable, -32003 PushNotificationNotSupported, -32004 UnsupportedOperation, -32005 ContentTypeNotSupported, -32006 InvalidAgentResponse, -32007 ExtendedAgentCardNotConfigured, -32008 ExtensionSupportRequired, -32009 VersionNotSupported; standard -32700/-32600/-32601/-32602/-32603.
- Version header `A2A-Version: 1.0`; an empty value means 0.3.
- **0.3 compatibility** (many clients still speak it, e.g. SDKs from 2025): methods `message/send, message/stream, tasks/get, tasks/cancel, tasks/resubscribe, tasks/pushNotificationConfig/{set,get,list,delete}, agent/getAuthenticatedExtendedCard`; parts `{"kind":"text","text"}`, `{"kind":"file","file":{"uri"|"bytes","name","mimeType"}}`, `{"kind":"data","data"}`; roles `user|agent`; states lowercase (`submitted, working, input-required, completed, canceled, failed, rejected, auth-required`); objects carry `"kind":"task|message|status-update|artifact-update"`; stream final flag `final`. The method name tells which dialect a request speaks, and the reply uses the same dialect. The 0.3 card is served at the same path with `?version=0.3` or `A2A-Version: 0.3`.

## Decisions
- **A separate listener** (like the phone gateway): `A2A_HOST` (default `127.0.0.1`) and `A2A_PORT` (default `8766`), started only while the owner has A2A switched on (page or `POST /api/a2a/enable`), persisted in the database so it comes back after a restart. Refuses to listen on a non-loopback host with no clients configured. The main API stays on 127.0.0.1.
- **Every caller is a registered client** the owner created on the page: a name, a token shown ONCE (`a2a_` + 43 random chars, only its SHA-256 stored, constant-time compare), allowed scopes, a rate limit (default 60 requests/min) and a limit of 5 running tasks. The public card and the docs page need no token; everything else does. Failed-token throttle per address.
- **Bindings:** JSON-RPC over HTTP (POST `/a2a`) with SSE streaming. gRPC and HTTP+JSON are not offered (the card lists only JSONRPC). Push notifications (webhooks) are supported with an SSRF-safe sender (https only, public addresses only, no redirects, 3 tries).
- **Each client gets its own bot** ("Agent: <name>", kind `agent`, visible in the sidebar so the owner sees every request and answer). Tasks of one client run through that bot's chat, strictly one at a time (so answers never mix; the next waits in `SUBMITTED`), with the normal orchestrator, phones, queue and approvals. `retrieve-context` and `store-context` are answered in code at once and never wait. A `contextId` is a conversation: tasks sent with the same contextId see the earlier ones.
- **Remote agents are untrusted.** What they send is a request from another program, never the owner: the bot's instructions say so; approval and handoff cards (sending, paying, installing, signing in, secrets, codes) can only be answered by the owner, so the task goes to `INPUT_REQUIRED` and waits (the answer comes from the owner's page, not the remote agent). Scopes are enforced in code, not by the model: `ask` (chat, knowledge, read-only connectors), `phone` (any phone action, link and APK checks, pictures), `context-write` (add to the shared knowledge). A scope a client lacks is refused with a clear error. No scope ever reaches secrets, the vault, other clients' traffic or owner-private bot memory.
- **Inputs:** `text` parts (the request), `data` parts (JSON: `{"skill": "...", ...}`), `raw` file parts (base64: pictures go through the image pipeline and become chat attachments, an `.apk` goes to the APK check, text-like documents (txt, md, json, csv, html) are read and stored, anything else is stored as a file record). `url` file parts are kept as references and NOT fetched (no server-side fetching of caller-chosen addresses). Limits: 64 KB of text, 30 MB per file, 40 MB per request.
- **Outputs:** the final answer as a text artifact `answer`; structured results as `data` artifacts (`verdict`, `search-results`); pictures, screenshots and reports as file artifacts with `url` (served by the A2A listener at `/a2a/files/<id>`, token required) plus `mediaType` and `filename`; progress as `statusUpdate` messages. Every task ends in a real state with a status message; a task that fails says why.
- **Everything is stored** (tables below) and replays: tasks, messages (history), artifacts, events (so a dropped stream can resume), push configs, clients, and the audit of every call (client, method, task, time, outcome; never tokens or file bytes).
- **One shared knowledge store** (`agent/knowledge.py`), replacing the per-bot memory table's role: bots, jobs, reports and A2A traffic all write to it; every bot reads what its visibility allows through one retrieval path (`knowledge_search`), and the old `memory_search` and `memory_save` actions are served by it.

## Knowledge store: the interface the A2A service builds on
Table `knowledge(id, text, title, kind, visibility, bot_id, client_id, context_id, task_id, source, tags, meta, created, updated, hash)` and an FTS5 index (porter stemming, unicode, prefix search) over title, text and tags.
- `visibility`: `private` (one bot), `bots` (every bot of the owner), `agents` (bots and A2A clients: what the owner published).
- Who sees what: a bot sees `private` entries of its own bot id plus all `bots` and `agents` entries; a client sees entries it created (`client_id`) plus `agents` entries; nobody else's traffic. Retrieval always filters in SQL, never after ranking.
- `Knowledge.add(text, *, kind, visibility, bot_id=None, client_id=None, context_id="", task_id="", title="", source="", tags=(), meta=None) -> int | None` (redacts secrets, cuts at 8000 characters, skips an exact duplicate, returns None if empty).
- `Knowledge.search(query, *, viewer, kinds=None, context_id=None, task_id=None, since=None, limit=5) -> list[Hit]` where `viewer` is `("bot", bot_id)` or `("client", client_id)`. Ranking: BM25 with title weighted over text, an AND match first and an OR fallback, a small recency boost, a boost when the whole phrase matches, near-duplicates collapsed. A `Hit` has `id, title, text, snippet, kind, visibility, bot_id, client_id, context_id, task_id, source, created, score`.
- `Knowledge.get(id, viewer)`, `Knowledge.recent(viewer, ...)`, `Knowledge.delete(id)`, `Knowledge.stats()`.
- Additions made while building it: the viewer `("owner", None)` sees everything (the page and `GET /api/knowledge`); `add(..., created=None)` keeps a given time (used by the migration); an exact repeat returns the EXISTING id instead of None; `search(..., visibilities=None)` and `recent(..., visibilities=None)` narrow to some visibilities; a `Hit` is a dict that also answers to attributes (`hit.text`, `hit["text"]`) and carries `tags` and `meta` too;
  `update(id, text=, title=, tags=)`, `delete_for_bot(bot_id)` (its private entries go, shared ones stay), `delete_for_client(client_id)` (everything a client created; call it when a client is removed), `erase_all()`. `db.knowledge` is the instance, `app.state.knowledge` and `orch.knowledge` point at it. The old `db.memory_add/memory_search` are private entries of kind `memory`.
- Kinds in use: `memory`, `note`, `task-result` (every finished job, visibility `bots`, `source` = job id), `report` (every Library report, visibility `bots`, `source` = library id). A2A code should use `a2a-message`, `a2a-artifact`, `a2a-file`.
- Retrieval quality is tested with a labelled corpus (recall@3 and MRR floor), morphological variants ("booked", "booking"), scoping (no leaks), filters and speed on 20,000 rows.

## Skills on the card
`phone-task` (do something on an Android phone), `ask` (an answer using the shared memory, no phone), `link-check`, `apk-check` (needs an APK file part), `show-me` (an illustration), `retrieve-context` (search the knowledge store), `store-context` (add a note to it). Each lists examples, input modes and output modes, and a JSON Schema for its `data` input at `/a2a/skills`. A human page at `/a2a/docs` shows the card, the skills, the auth steps and copy-paste examples; `scripts/a2a_client.py` is a small working client (send, stream, get, cancel, retrieve).

## Not in v1 (said honestly)
gRPC and HTTP+JSON bindings, OAuth/OIDC for callers (bearer tokens only), signed agent cards, fetching `url` file parts, tenants, semantic (embedding) retrieval (a model-free index only: the Muse API has no embeddings endpoint that was verified), and multi-owner use.

## Status: knowledge store (3 Nov 2026)
Built: `agent/knowledge.py` (table, FTS5 index with porter stemming, visibility enforced in SQL, secret redaction and account masking on write, exact-repeat dedupe, near-duplicate collapse on read), the one-time move of the old per-bot memory into it, `db.memory_*` served by it, the bot actions `knowledge_search` and `knowledge_save` (and `memory_search` now also returns shared notes), every finished job and every Library report written to it for all bots, `GET /api/knowledge` and `DELETE /api/knowledge/{id}` for the owner, and the wipe-everything path clearing it.
Tests: `tests/test_knowledge.py` (35): who sees what for every viewer, hostile query strings, stemming and spellings (Wi-Fi, e-mail, log in), phrase and all-terms ranking, recency, dedupe, filters, migration, memory compatibility, 20,000-note speed, the bot actions, and the job and report hooks.
Retrieval eval (60 realistic notes, 40 queries written as other words, other forms and extra noise): recall@1 0.97, recall@3 1.00, MRR 0.988. Search over 20,000 notes: median about 6 ms, worst about 25 ms.
Known limits: no meaning-based matching (no embeddings): questions with no shared word with the note, such as "wake me up at quarter to seven" for an alarm note, mostly fail (2 of 4 such probes found it in the top 3, by luck of a shared word); a misspelled main word is not corrected ("alram" finds nothing; a typo next to a correct word still works); compound words are only unified for a short list (wifi, email, setup, login, signin, backup); the owner's own bots see every `bots` entry, so anything an A2A task leaves with visibility `bots` is readable by all of them.

## Status (3 Nov 2026): protocol service built
Files: `agent/a2a.py` (storage, dialects, card, skills table), `agent/a2a_rpc.py` (auth, JSON-RPC dispatcher, state, events, owner views), `agent/a2a_exec.py` (executor and the bot gate), `agent/a2a_server.py` (the door, docs page, files, push sender, on/off switch, management routes), `scripts/a2a_client.py`, `tests/test_a2a.py` (39), `tests/test_a2a_exec.py` (25).

Differences from the plan above, and what was decided while building:
- **Blocking defaults follow each dialect's spec:** 1.0 `SendMessage` waits up to 25 s unless `returnImmediately` is true; 0.3 `message/send` returns at once unless `blocking` is true. A blocking call that is still going after 25 s returns the working task.
- **One task at a time per caller** (the caller's bot has one chat; two at once would be answered together by one model turn). Further tasks wait in `SUBMITTED` and can be cancelled before they start. The deterministic skills are exempt.
- **The bot that serves a caller (kind `agent`) is gated in code** (`Executor.gate`, hooked into the orchestrator's turn loop as `orch.action_gate`): no `ask_bot`, `request_secret`, `vault_check`, routines, connected apps (`connector_call`) or `web_options`; its context has no vault labels, other bots or connected apps; `knowledge_search`, `memory_search` and `knowledge_save` are answered by the gate with the CALLER's viewer (`("client", id)`), so an outside agent never sees other callers' traffic, the owner's private notes or notes the owner's bots share among themselves; phone actions and pictures need the `phone` permission; the `ask` skill never uses a phone even when the caller may.
- **Skills run in code, without a model:** `retrieve-context`, `store-context`, `link-check` (queues the checked-report job itself), `apk-check` (calls the APK check directly), `show-me` (calls Muse Image directly). The rest go through the orchestrator.
- **Outputs:** `answer` (text), `job-results` (data: each phone task's goal, status and result), `verdict-*` (data), `report-*` and `report-markdown-*`, `picture-*`, `screenshot-*` (files with `url` on the door), `search-results`, `stored`. Status updates carry the bot's progress lines. Text passes through `scrub`: internal phone names become Phone / Phone 2 and `(SomeError)` class names are removed.
- **Everything is stored in the database and the shared knowledge:** inbound text and documents, files (record), answers, artifacts and status text, as visibility `bots` entries with `client_id`, `context_id`, `task_id`, `source a2a:<name>` and kinds `a2a-message`, `a2a-artifact`, `a2a-document`, `a2a-file`, `a2a-note`. The two deterministic skills do not store their own query. A purge (`DELETE /api/a2a/clients/{id}?purge=true`) removes the caller, tasks, messages, artifacts, events, push configs, files on disk and its knowledge (`delete_for_client`); a plain revoke keeps the history.
- **Job completion is polled** (every 0.5 s from the task thread) rather than observed through a hook, so the orchestrator only gained `action_gate` and three small `_context` conditions.
- Unknown `contextId` values from a caller are accepted when they match `[A-Za-z0-9._:-]{1,100}` (SDKs often invent their own); every context is keyed by caller, so two callers can never share or probe one.
- A finished task refuses more messages with -32004 (the spec says to start a new task in the same context).
- Push webhooks are checked twice: the address shape when registered, the resolved addresses (public only) at send time; credentials are never echoed back.

Owner management API (main app): `GET /api/a2a`, `POST /api/a2a/enable|disable`, `POST /api/a2a/clients` (`{name, scopes, rate_per_min, max_running}` returns `{client, token}` once), `POST /api/a2a/clients/{id}/rotate`, `DELETE /api/a2a/clients/{id}[?purge=true]`, `GET /api/a2a/tasks?client=&limit=`, `GET /api/a2a/tasks/{id}`. The page receives `{type:"refresh", what:"a2a"}` on every bot stream when anything changes.

Verified live (real Muse models, real listener, the client script): store and retrieve, the `ask` skill, a free-text task that used the shared notes, and the refusal of `phone-task` for a caller without the `phone` permission. Not verified live: a real phone task over A2A, `link-check`, `apk-check` and `show-me` against real phones and Muse Image (covered by tests with fakes), webhooks to a real public receiver, and use from a third-party A2A SDK client.
